## 1. Introduction
QuantumBTC is built on the principle of "Don't Trust, Verify". This document specifies the mechanisms that allow players to independently verify that every spin of the roulette is mathematically fair, unpredictable, and unbiasable.

## 2. The Verification Model
We utilize a **Hybrid Quantum-Public Entropy** model. This ensures that even if the casino were compromised, it cannot manipulate the outcome because the final result depends on external, verifiable data sources.

### 2.1 Sources of Entropy
1.  **Quantum Entropy (ANU QRNG):** Real physical randomness from quantum vacuum fluctuations provided by the Australian National University.
2.  **Public Beacon (drand):** A decentralized network of nodes (League of Entropy) that produces a verifiable random value every 3 seconds.
3.  **Client Seed:** A unique 64-character hex string generated locally in the player's browser before the bet.
4.  **Server Seed:** A secret value generated by the backend for each round.
5.  **Bet ID:** The unique atomic identifier of the transaction.

## 3. The Provably Fair Formula
The final outcome is the result of a deterministic SHA-256 hash mixing all entropy sources:

```javascript
const final_entropy = SHA256(
  server_seed + 
  client_seed + 
  drand_randomness + 
  anu_quantum_bytes + 
  bet_id
);

const outcome = final_entropy % 37;
```

## 4. Verification Workflow for the Player
The "Verify (Fair)" page must provide a step-by-step tool for players to audit their history.

### 4.1 Data Exposure (Post-Game)
Once a bet is resolved, the following data points must be available in the "History" and "Verify" sections:
- **Client Seed:** (Provided by the browser)
- **Server Seed:** (Revealed once the bet is settled)
- **drand Round:** (The specific round number used)
- **drand Randomness:** (The hex value of that round)
- **ANU Bytes:** (The specific hex segment pulled from the buffer)
- **Bet ID:** (The database UUID)

### 4.2 The "Interactive Verifier" Tool
The page must host a UI component with:
1.  **Input Form:** Fields to paste the values above (or an "Auto-fill from History" button).
2.  **Calculation Step:** A visual breakdown of the SHA-256 operation.
3.  **Cross-Check:** Links to the [drand explorer](https://drand.love/explorer/) to prove the `drand_randomness` matches the official record for that `round`.

## 5. UI/UX Requirements for Verification
- **Tone:** Academic but accessible. Use clean typography and clear labels.
- **Visuals:** Use icons representing Quantum (atoms), Public (network), and Private (keys).
- **Security:** Ensure the verifier logic runs client-side (Javascript) so the user doesn't have to trust the server to "verify" itself.

---

> [!IMPORTANT]
> A bet is "Auditable" only after resolution. The Server Seed must remain secret until the payment is confirmed to prevent pre-calculation attacks.
