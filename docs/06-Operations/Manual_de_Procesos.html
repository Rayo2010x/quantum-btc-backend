1. Actores y Responsabilidades

Definición de los roles técnicos involucrados en la ejecución de la lógica de negocio.

Actor Etiqueta Responsabilidad Principal
Usuario Final User Iniciar la sesión, seleccionar apuesta, realizar pagos LN y reclamar premios.
Frontend (Next.js/Vercel) Frontend Interfaz visual, polling de estados, presentación de QRs.
Backend API (Node.js/Railway) Backend Orquestación central, validación de reglas, cálculo de resultados, control de pagos.
Base de Datos (PostgreSQL/Supabase) DB Persistencia transaccional, bloqueo de filas (row-locking), almacenamiento de entropía.
Entropy Worker Worker Proceso background que mantiene el buffer de entropía cuántica lleno.
OpenNode (Payment Provider) OpenNode Proecesamiento de pagos Lightning Network (Invoices y Withdrawals).

2. Matriz Detallada de Procesos

Desglose paso a paso desde el inicio de sesión hasta el cobro del premio.

Fase 1: Inicialización y Colocación de Apuesta

# Acción / Proceso Responsable Detalles Técnicos (Data & State)
01 Inicio de Sesión (Anónimo) User ➜ Backend POST /v1/session/init. Se crea registro en tabla sessions. Retorna sessionId. No requiere auth profunda.
02 Selección de Apuesta y Envío User ➜ Backend El usuario envía números y monto. POST /v1/game/bet.
03 Validación de Límites (Bankroll) Backend Verifica que amount < MAX_BET_SATS. MAX_BET se calcula dinámicamente basado en (Bankroll - Floor) / K.
04 Reserva de Entropía y Creación de Invoice Backend ➜ OpenNode 1. DB: Marca 1 bloque de entropía como is_consumed=TRUE (Reserva).
2. OpenNode: Genera Invoice (Charge) por el monto de la apuesta.
3. DB: Inserta registro en bets con status WAITING_PAYMENT, server_seed_hash (Commitment) y link al invoice_id.
05 Presentación de Invoice QR Backend ➜ Frontend Retorna el string BOLT11 al usuario para que lo pague con su wallet.

Fase 2: Ejecución del Juego (Pago Confirmado)

# Acción / Proceso Responsable Detalles Técnicos (Data & State)
06 Pago de Invoice User ➜ OpenNode Usuario escanea y paga. OpenNode detecta el pago en LN.
07 Recepción de Webhook OpenNode ➜ Backend POST /v1/webhooks/opennode. El Backend verifica la firma HMAC-SHA256 para autenticidad.
08 Bloqueo y Ejecución (Critical Path) Backend ➜ DB 1. DB Lock: SELECT ... FOR UPDATE sobre la apuesta para evitar doble gasto.
2. Reveal: Recupera la entropía reservada (ahora revelada como server_seed).
3. Cálculo: Result = SHA256(ServerSeed + ClientSeed) % 37.
4. Update: Actualiza bets a WON o LOST y guarda final_result.
09 Generación de Token de Retiro (Solo Ganadores) Backend ➜ DB Si ganó: Genera un secreto k1 y crea registro en withdrawal_tokens válido por 24h. Vincula este token a la apuesta.

Fase 3: Notificación y Cobro

# Acción / Proceso Responsable Detalles Técnicos (Data & State)
10 Polling de Estado Frontend ➜ Backend El Frontend consulta regularmente el estado de la apuesta. Recibe WON y el payload del LNURL-withdraw.
11 Visualización de Resultado Frontend Muestra animación de ruleta deteniéndose en el número resultante. Si gana, muestra botón "Cobrar" (QR LNURL).
12 Solicitud de Retiro (Scan) User ➜ Backend Wallet escanea QR. GET /v1/lnurl/withdraw?k1=.... Backend valida token no usado y no expirado.
13 Ejecución de Pago Saliente OpenNode ➜ Backend Wallet envía Invoice de cobro al callback. Backend valida y ordena a OpenNode pagar la factura (OpenNode.payInvoice). Marca token como is_used=TRUE.

3. Controles y Procesos de Fondo

3.1 Entropy Buffer (Mecánica de Llenado)

Responsable: Entropy Worker Service (src/services/entropy_worker.ts) Frecuencia: Polling cada 5 segundos. PROCESO: 1. Consultar conteo DB: `SELECT COUNT(*) FROM entropy_buffer WHERE is_consumed = FALSE` 2. Si count < BUFFER_TARGET (100): a. Calcular faltantes (ej. faltan 10). b. Request HTTPS a API ANU Quantum (o fallback a Crypto nativo si falla). c. Iniciar transacción DB. d. INSERT masivo de bloques hexadecimales. e. COMMIT. 3. Dormir 5s y repetir.

3.2 Protección de Bankroll (Gestión de Riesgo)

Responsable: Bet Route (src/routes/bet.ts) Momento: Antes de crear cualquier Invoice. REGLA: MAX BET DINÁMICO Formula: MaxBet = (Current_Balance - Reserved_Funds - FLOOR) / Safety_Factor Donde: - Current_Balance: Fondos reales en OpenNode. - Reserved_Funds: Suma de withdrawal_tokens activos (ganados pero no cobrados). - FLOOR: Mínimo operativo (ej. 400,000 sats). - Safety_Factor: Divisor para exponer solo una fracción del excedente (ej. 50). Si la apuesta > MaxBet, el sistema rechaza inmediatamente con error 400.
